## 四、关键发现（均可通过 `run-2026-08-18-k3relay.json` 对应 `case_attempts` 追溯完整请求/响应体）

1. **`video_base64` 被中转以 HTTP 400 拒绝**：返回 `{"error":{"code":"400","message":"{\"error\":{\"message\":\"Invalid input\",\"type\":\"invalid_request_error\",\"param\":\"messages.0.content\"}}","traceId":"..."}}`。即视频 content part 的假设 schema（`{type:"video_url", video_url:{url:"data:video/mp4;base64,..."}}`）不被新 k3 中转（we2ai）接受，`messages.0.content` 被判定非法。这与 PDF 未给出视频输入 schema 的已知假设有关（见 SCHEMA.md 未决项 1），需要在联调时向供应商核实视频 content part 的实际 schema，当前按冻结的假设 schema 构造请求必然失败。

2. **`tool.choice_allowed_tools` 被中转以 HTTP 400 拒绝**：返回 `{"error":{...,"param":"tool_choice"}}`。即 `{type:"allowed_tools", allowed_tools:{mode, tools}}` 这一 OpenAI 现行草案格式不被新中转识别，`tool_choice` 字段被判定非法。该格式本就是 SCHEMA.md 未决项 2 标注的"待联调核实"假设，本次实测确认新中转不支持该草案格式。

3. **思考开关 4 种方式均无法真正关闭思考**（与 2026-08-17 tokenpanel 网关表现一致）：`enable_thinking:false` / `thinking:{"type":"disabled"}` / `chat_template_kwargs.enable_thinking:false` / `chat_template_kwargs.thinking:false` 四种请求均返回 HTTP 200，但响应仍携带非空 `reasoning_content`。值得注意的是，本次新中转对 `chat_template_kwargs.*` 参数**没有**像 tokenpanel 网关那样返回 400 拒绝，而是接受该参数但静默忽略、继续输出思考内容——即参数被透传但不生效。开/关两次请求本身都成功送达并拿到合法响应，只是关闭开关未生效，属模型/网关侧真实行为。

4. **`reasoning_effort` 三档的 `reasoning_tokens` 实测**（每档 3 次采样）：low=1307/3910/657、high=1063/4123/1385、max=1128/899/1083。low 档 3 次采样结果分散（1307/3910/657）未形成严格多数，众数聚合判定失败。9 次请求全部成功（attempts=9 passed=9），只是同一档位下输出长度波动极大（low 档单样本 3910 反而高于 high 档多数样本），`reasoning_effort` 对推理量的影响不稳定、非单调递增，与 tokenpanel 网关 2026-08-17 的观察一致。

## 五、已知限制（非本次测试范围内可解决）

- `image_url` / `video_url` 未测试：无公网可达素材托管地址（与 tokenpanel 测试一致），留待部署阶段补测。
- `reasoning_effort` 众数聚合在 `repeat_attempts=3` 高方差场景下易判"无多数"，是否需要提高采样次数或改用区间判定是后续设计取舍。
